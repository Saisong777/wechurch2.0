# 500 人教會模擬與驗收

## 判定原則

這是一份可重跑的工程驗收，不是「所有情境永遠不會出錯」的保證。
功能正確、權限安全、效能、操作體驗、外部服務和實際營運分開判定。
未實作、未測、被功能旗標關閉的功能不能算通過。

執行基準：目前 B 分支 `codex/bible-study-integration`；A 不部署，B 真實資料不重置。
本輪結果及修正後重跑紀錄見下方「結果」。

## 教會模型

| 身分／結構 | 數量 | 模擬方式 |
| --- | ---: | --- |
| 已在小家的使用者 | 450 | 30 家，每家 15 人，含 1 位小家長 |
| 牧區負責人 | 5 | 每人授權管理 6 家；不自動取得私人筆記或小家分享內容 |
| 主任牧師 | 1 | 本教會管理與授權 |
| 系統管理員 | 1 | 系統管理，不因管理員身分自動出現在牧養概況 |
| 傳道人／儲備領袖／舊 leader 角色 | 各 1 | 不預先指定小家，測沒有責任範圍的狀態 |
| 尚未加入小家的新人 | 40 | 可先讀經、記筆記與禱告，再申請及經批准加入 |
| 合計 | 500 | 500 個不同會員 ID、session 及私有資料擁有者 |

**牧區限制：** 目前沒有原生牧區組織樹、牧區設立／合併／任期 UI。
這裡的五個牧區以現有 `crm_scope_assignments` 每人六家實現，不把測試名稱當成已完成的牧區模組。
緊急探訪是同教會牧者共用收件匣，不是五個彼此隔離的探訪信箱。

## 500 人連貫情境

- 500 人確認登入歸屬；最初都沒有小家，之後建立既有 450 人的小家關係。
- 500 人各存一篇筆記、一則私人禱告、一篇恩典紀錄、一位關懷對象與一筆經文收藏。
- 逐人讀回全部私有資料；下一位會員嘗試修改他人筆記／禱告、查看關懷歷史，必須拒絕。
- 450 人完成小家共同讀經，各分享自選筆記摘錄與匿名禱告；相鄰小家無權查看。
- 30 位小家長查看匿名分享、留言，記錄聚會出席及共享關懷；未填出席不得被當成缺席。
- 五位牧區負責人只能管理六個被授權小家；沒有勾選個資授權時，名單不可包含會員 email。
- 30 個探訪轉介：沒有同意不能送出、只顯示分享摘要、多人接案只有一個成功、取消後不可再完成。
- 30 則匿名公開禱告：愛心重試、鼓勵留言、成就後關閉公開分享，私人原文仍在。
- 40 位新人提出申請；批准前不可查看小家，批准後不可讀到加入前的分享。
- 30 位使用者雙裝置同時存筆記：一個成功、一個版本衝突；相同建立請求重試只能有一篇。
- 30 人轉家、退出；舊小家即時拒絕，新家歷史不外洩，個人筆記保留。
- 撤銷五位牧區負責人的全部授權，既有 session 不得保留舊範圍。
- 正版研經資料校驗、四個譯本、註釋切換、希臘／希伯來文、原文字典、串珠預覽、搜尋及非法參數。
- 10／50／100／250／500 並行 HTTP 客戶端各 1,000 次請求；另 100 並行、約 50 秒節奏化 5,000 次混合請求。
- 負載後比對資料筆數，並測 session version 撤銷；瀏覽器另走手機及桌面主要旅程。

## 全功能覆蓋矩陣

除 500 人模型外，完整既有測試另外執行，避免將它們的會員夾入 500 人計數。

| 模組 | 補充情境／證據來源 | 驗收邊界 |
| --- | --- | --- |
| 登入與身分 | `verify-auth-security-http.ts`、Google／LINE identity、安全單元測試 | 合成 session 不代替真人 Google 同意；外部寄送關閉 |
| 每日靈修／匯入 | `churchDevotion.test.ts`、`churchDevotionFile.security.test.ts`、integrity worker | CSV／Excel／Sheet 映射、惡意壓縮檔、版本還原；Sheet 網路回應包含 mock |

| 筆記／收藏 | 500 模型、integrity worker、`useDevotionalNotes` 等前端測試 | 草稿、讀取失敗、重試、衝突；離線跨裝置並非全數實測 |

| 靈修牆 | 500 模型、devotion wall 測試、security browser | 台灣換日、摘錄、分頁與撤回；時界測試包含受控時間 |
| 小家 | 500 模型、`verify-family-http.ts` | 目錄、配對申請、邀請輪換、批准、轉家、封存、留言 |
| 牧養概況／出席 | 500 模型、`verify-leader-dashboard-http.ts` | 範圍、歷史、匿名、交接、衝突與聚會取消 |
| 關懷／探訪 | 500 模型、`verify-care-http.ts` | 歷史、封存還原、同意、接案競態、取消與撤權；不保證站外即時通知 |
| 求助／轉交 | `verify-support-http.ts` | 承接、本人同意轉交、私人同工備註不傳給下任、取消與重新開啟 |
| 愛的旅程／門訓 | `verify-support-http.ts`、`verify-mentoring-http.ts` | 課程快照、私人回答、雙方同意、結束／退家撤權；測試旗標開啟不等於 B 對會員開放 |

## 安全隔離與可重跑性

```sh
npm run build
RUN_SECURITY_BROWSER=1 npm run test:church500
npm run test:church500:history
npm run test:integrity
npm test
```

需要 Node 22、localhost PostgreSQL，以及已驗證的 `bible-study-data` 和既有 Playwright CLI。
不用新增套件；不讀 B 的私人資料。DB URL 僅可為 loopback，而且必須由父程序新建隨機名稱資料庫。
父程序不繼承供應商金鑰／Railway 環境，停用郵件和晨間摘要；結束時刪除測試 DB 並讀回確認不存在。
正式 API read/write/ingress 限流保留；管理者批次準備階段在客戶端放慢，負載階段不繞過保護。
結果含執行 ID、來源 commit、測試程式 SHA-256、HTTP 狀態、每個情境、p50/p95/p99、pool 排隊與 RSS。
固定功能情境使用相同結構；UUID、時間和主機速度每次不同。

負載通過條件：預期成功請求沒有非 2xx、無網路／格式錯誤、各階段 p95 < 2 秒、儲存後筆數吻合。
403／404／409 等只有在負面情境**明確預期**時才算通過，不把所有 4xx 都視為正常。
RSS 是同機 client＋server 程序，不得直接當作 Railway app 的記憶體需求。

## 結果

### 核心情境：有範圍限制地通過

來源 `5a3ccac3691bfe92900aea56e5e6080654fc80d7`；本機 Node 22.22.2／arm64、20 個 PostgreSQL 連線。
執行 `5687a9e4-01a7-4856-a211-a78db30644f5`：22 組連貫情境、20,294 次 API 請求通過；負面測試的 400／401／403／404／409 均按預期斷言。
10,000 次混合負載（80% 讀、20% 寫）無非預期錯誤；儲存後 2,501 篇筆記及其他私有紀錄筆數吻合。

| 同時 HTTP 請求 | 請求數 | p95 | p99 | 非預期錯誤 |
| ---: | ---: | ---: | ---: | ---: |
| 10 | 1,000 | 20 ms | 29 ms | 0 |
| 50 | 1,000 | 88 ms | 93 ms | 0 |
| 100 | 1,000 | 185 ms | 192 ms | 0 |
| 250 | 1,000 | 490 ms | 514 ms | 0 |
| 500 | 1,000 | 937 ms | 1,135 ms | 0 |
| 100，約 50 秒節奏化 | 5,000 | 113 ms | 125 ms | 0 |

500 並行時 pool 等候最高 480；短時間尖峰雖過關，仍須觀察正式規格的長時間排隊與超時。
同程序 client＋server RSS 峰值 495 MiB，不能解讀為 Railway 記憶體規格建議。

同一隔離模型上的瀏覽器驗收 `44066ac9-88c4-4998-a263-7321a323d717`：390／1440px 共 21 項通過；包含小家留言的同意／保存、牆與個人分享分頁、CSP、舊入口導向。代表截圖已人工讀圖。
既有回歸：116 個測試檔、636 項測試、36 項部署測試、完整隔離 HTTP／資料庫回歸、型別及建置通過。Lint 為 0 errors、290 warnings，不宣稱零警告。

### 已找到並修正的權限問題

牧師／傳道人角色原本會把限定能力的額外 CRM 授權提升成其他能力，導致未勾選個資的範圍也能看見 email。
修正只收緊額外授權，保留本人與實際任職小家的既有權限；多份有效授權仍採合法能力聯集。
已新增兩種角色的反向測試，並用 B 站三個臨時帳號重現修正前問題；臨時資料已清除。
修正後 B 線上驗收待本次發布完成，不能以本機結果替代。

### 半年資料量

另加 90,000 篇歷史私人筆記（500 人各 180 篇），以 25／100／250／500 並行重測完整筆記讀取及寫入。
執行 `715234a3-ffbc-4686-aacc-4a9d143f25f8` 通過；每階段 1,000 次，合計 4,000 次（60% 私人筆記列表、20% 經文、20% 寫筆記），無錯誤。
800 次新增皆保存，最終 93,301 篇筆記吻合；測試資料庫已刪除並驗證不存在。

| 同時 HTTP 請求 | p95 | p99 | 同程序 RSS 峰值 |
| ---: | ---: | ---: | ---: |
| 25 | 109 ms | 129 ms | 416 MiB |
| 100 | 350 ms | 562 ms | 443 MiB |
| 250 | 800 ms | 806 ms | 499 MiB |
| 500 | 1,684 ms | 2,120 ms | 607 MiB |

**效能風險仍存在：** `getDevotionalNotes` 目前回傳本人的全部可見筆記。半年資料量每 1,000 請求共回傳約 116 MiB 未壓縮內容，500 並行 p99 已超過 2 秒。
本輪預先設定的門檻是 p95 < 2 秒，因此判定通過，但不隱藏尾端延遲。下一步應以向後相容的游標分頁、日期查詢和獨立完整匯出流程改善，不能直接限制回傳筆數而造成舊筆記像遺失。
歷史資料是固定長度的合成內容，並未模擬每位會員多年長篇筆記；本機短跑不等於 Railway 長期容量。

## 不能省略的正式上線門檻

1. Railway 等規格隔離環境長時間負載、冷資料與慢網路、重啟／故障恢復；不在含真實筆記的 B DB 塞 500 個人壓測。
2. 真正的牧區生命週期、代理與交接，急件未接手／逾期升級以及通知送達證據。
3. 真人 Google、實體手機、輔助科技、跨裝置離線恢復，及教會保護與申訴的政策驗收。
4. 門訓／愛的旅程一般會員開放驗收；多教會隔離、定期異地備份與獨立金鑰復原仍是另行門檻。

沒有完成以上項目之前，只能說「列明情境的工程模擬通過」，不能說「500 人正式營運全面認證」。
