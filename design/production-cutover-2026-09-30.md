# WeChurch 新正式環境部署與切換接續

## 狀態

2026-09-30：Sai 已授權用 B 新版本取代舊 A。新正式環境已獨立部署並通過下列檢查，**正式網域尚未切換**。這是取代專案的準備完成紀錄，不是正式上線完成紀錄。

舊 A 的應用、資料庫和 B 均保留。新服務沒有接上 `main` 自動發布；不能把舊 `main` 合併或部署到這個新服務。此次以 B 資料重建另一個正式資料庫是 Sai 明確授權的特定移轉，不改變一般 A/B 資料隔離規則，也沒有覆蓋舊 A 資料庫。

機器可讀的精確來源、部署及驗收界線見 [發布紀錄](releases/a-replacement-2026-09-30.json)。私密設定、會員原始資料、加密備份、操作接續與截圖不提交 Git。

- B 復原集實際還原 110 表，內容摘要、上傳檔、聖經資產及設定核對一致。新正式副本刻意清空 `auth_sessions` 和 `sessions`，沒有沿用 B 登入狀態；其餘 public 資料在舊來源差異補入前與備份一致。

- 新應用內部主要路由、health、Google 啟用狀態、正式 origin／callback 設定驗證通過。公開 HTTPS 驗收網址能載入首頁、聖經及每日靈修；390px 聖經畫面沒有橫向溢位，經文與圖片可見。這不等於實體 iPhone 驗收。

- 舊 A 資料庫加密備份已在隔離 PostgreSQL 完整還原出 40 表。**舊 A 上傳檔未取到**，不將資料庫還原當成整個 A 可恢復。

## 必須保留的未完成界線

1. 舊 A 應用無法讀取上傳檔；不要用重啟／重新部署嘗試救檔，避免 ephemeral 檔案被替換。已詢問 Sai 是否接受保留舊服務、待其他驗收通過後切換的例外，尚未取得回覆。未確認前不改切換保護條件。
2. B 與舊 Firebase 仍可寫入，尚未進入切換維護窗口；不能把此副本視為零遺失的最後狀態。正式切換前必須安排停止舊入口新增、再取最新加密快照／差異、演練與核對。若新正式驗收環境已出現任何非合成的新資料，不得用還原覆蓋，先另外備份並處理差異。
3. 正式 DNS／Railway 自訂網域及 HTTPS 未切換。正式主站規劃為 `www.wechurch.online`，apex 需同站或可驗證的 HTTPS 導向。不能直接抄 preview CNAME 當成 custom-domain target；必須讀回 Railway 實際要求的 CNAME／驗證值。既有 Email MX、SPF、DKIM、DMARC 及其他網站 DNS 不動。
4. 完整 Google 登入只能在正式 callback 路徑可用後驗收：登入原會員、讀回其舊筆記、確認不重複註冊，並測試登出及再次登入。現行保護工具比這一步更保守，尚未實作 DNS 切換操作；要先將「切換前設定核對」與「切換後真實登入／不開放時回退」寫成兩階段保護，不可偽填 `googleLoginVerified=true` 繞過。
5. 正式站需自己的限權 Resend 寄信金鑰、寄件網域驗證、一封核准的測試信及提醒同意／排程分工驗收。測完再啟用；避免 A、B 對同一會員重複寄信。
6. 最終資料與正式網址的加密備份、手機／桌面、會員與管理者操作，以及發布後監測／金鑰獨立復原保管仍需完成。先前 B 實機或 500 人情境模擬不能當成新正式環境的實機／容量認證。

## 接續順序

1. 讀私人操作接續及本紀錄，確認新服務 IDs、來源指紋、備份及 Sai 對舊 A 上傳檔例外的回答。原 A／B 權限、資料及域名不可被本操作工具當成 replacement target。
2. 讀回 Railway 目前的網域狀態。先前平台有控制台及 networking 異常，第一次產生驗收網域結果不明；復原後已實際讀回空清單，再產生唯一驗收網域並讀回成功。不得盲目重試任何結果不明的 mutation。
3. 完成維護窗口、B／舊來源最終差異同步和新環境實際資料核對。不要重新執行 `database` 還原到非空資料庫；此命令故意拒絕。
4. 準備可回復的 DNS／域名兩階段切換，保留舊 CNAME、網域歸屬、TLS 及回退方式；切換後未通過真正 Google 登入或私密資料讀回時不得宣布上線。
5. 通過正式寄信、功能及手機驗收，保存最後 production release record，才正式開放。B 保留作為獨立測試站，後續不與正式資料庫共用。

## 安全操作工具

`ops/prepare-production-replacement.mjs` 建立新資源及保護性備份；`ops/deploy-production-replacement.mjs` 還原新空資料庫、發布固定快照及傳送核對檔案。它們的 attempt checkpoint 不應在不清楚雲端結果時重設。

`ops/verify-production-replacement.mjs` 提供 `data`、`files`、`legacy`、`smoke`、`privacy`；`legacy` 不允許盲目重跑已嘗試的匯入，先檢查既有結果。`privacy` 只建立自己產生的合成資料，會清理精確 IDs，不輸出會員內容。

`ops/production-domains.mjs` 只檢查／產生新服務的驗收網域，**不改正式 DNS**。`ops/download-offsite-proof.mjs` 接受受限短效下載地址並核對加密檔案，不保存下載地址。`ops/rehearse-production-data.mjs old-a-database` 只驗證舊 A 的資料庫，不產生「完整 A 復原」證明。

私密工作根目錄為 operator home 下 `.local/share/wechurch-migration/production-cutover-20260930`；所有 credentials、設定、下載原件及會員內容都在 Git 之外。
